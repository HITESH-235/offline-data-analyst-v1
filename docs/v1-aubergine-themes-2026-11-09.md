# V1 aubergine / citron / coral themes

Light uses pale lilac workspace surfaces, white cards, aubergine text and purple primary actions. Dark uses purple-black workspace surfaces, raised purple cards, lilac secondary highlights and citron primary actions. Both keep dark aubergine navigation with citron active states. Borders, state colors, focus, code/Markdown, data grids, saved analyses, chat and Plotly presentation share semantic CSS tokens. The terminal favicon matches the new identity.

The accessible top-bar Theme selector offers Light, Dark and System. A small synchronous inline head bootstrap resolves the preference before app paint, without a theme-script fetch. The preference uses its own localStorage key (`analyst-theme`). System mode listens to OS changes; fixed modes stay fixed; reload, invalid/stale preferences, blocked storage and cross-tab updates are covered by tests. The control stays available in the existing narrow single-pane layout.

Both table-result charts and custom Python Plotly artifacts use the same presentation adapter. Mounted graphs update using Plotly.react with stable uirevision, preserving ranges and legend state. Theme changes do not change chart data, rerank results, refetch figure JSON or remount the workspace. Default legacy/Plotly palettes migrate to the new colors; custom nondefault series styles, values, scales, frames and annotations are retained. Comparison series have distinct default markers/dashes. Bar values get contrasting inside text. Correlation traces, including Plotly Express shared color axes, remain diverging with -1/+1 limits and zero center. PNGs remain untouched on a neutral white image surface, with existing aspect ratio/full-size behavior.

Verification used no model calls and no browser automation. All five frontend test files passed; the production build passed separately in 543 ms. The tests cover the actual inline bootstrap, preference/system events, shared palette contrast, six table chart types, generated figures, correlation/shared color axes, custom styling, stable view revisions and chart-label contrast. Saved Northwind ranking (77 rows), correlation (3 rows), and the two-year monthly comparison (12 rows, two series) were also checked offline in both themes: plotted values and revisions are unchanged. There are no new UI dependencies.

Programmatic contrast: 136 explicit adjacent token pairs pass. Light normal text minimum is 4.94:1 and meaningful control minimum 3.16:1; dark minima are 5.82:1 and 3.69:1. Decorative separators/gridlines intentionally remain subtle. The original light coral had only 4.38:1 on raised lilac; error text now uses #AD3548 while #B83D4E remains the accent/series color. Full ratios and checks are in the evidence files below. These checks cover app/default chart styles; arbitrary custom figure colors may still need visual review.

61 backend and critical frontend analysis/context/result/data-model file hashes match the pre-theme version. Calculation, publication and saved-analysis persistence contracts were not changed. Only the separate theme preference is new. Existing pane layout, resize/collapse controls and analysis flows are retained.

## Browser checklist

Use existing saved results; do not generate new analyses for these checks.

1. Select **Light**, then **Dark** in the top bar. Reload in each mode: the selection should persist with no bright first frame. Tab through the selector, navigation, inputs and action buttons; check visible focus and readable selected/disabled controls.
2. Select **System** and change the OS/browser `prefers-color-scheme` between light and dark. The app should follow immediately. Select a fixed mode and repeat the OS change: it should stay fixed. Reload System mode and confirm it follows the current OS preference.
3. While browsing **Northwind → Customers**, open the saved **Products × Order Details** ranking. Check table headers, numeric alignment, sorting, pagination, selected/hover states, Top 5/10 chart controls and collapsed calculation details in both themes. Source and browsed dataset must remain distinct. Theme switches should preserve the table page/sort and chart field choices.
4. Open the saved two-year monthly result in project `q04-repair-live-2026-11-09 2026-11-09 18:00:42`. Expect 12 rows, two distinct line series, unchanged values and source. Open a saved generated Plotly figure, zoom and hide a legend series, then switch themes: the view should remain. Check axes, labels, hover cards and modebar. A saved correlation must retain -1/+1, zero center and visible coefficients. A saved PNG should keep its original colors/aspect ratio on white; its full-size link should still work. Theme changes should add no backend requests in the Network panel.
5. Review existing chat replies with Markdown tables/code and an existing failed reply. Check Open result cards and Saved Analyses. For a pending-state check, replay a captured progress stream rather than call the model. Check pending/completed/failed/incomplete status styling and elapsed-time readability. Inspect existing rename/delete confirmations too: these remain native browser dialogs and their OS chrome is controlled by the browser, while form controls use color-scheme.
6. At about **390 px** and **900 px**, check that the theme selector remains reachable, Projects/Data/Chat single-pane navigation works, dropdowns/labels fit, and tables/plots scroll cleanly. Return to desktop, resize and collapse both panes, and confirm the canvas stays in its intended column.

Browser rendering, actual first-frame appearance, keyboard interaction and native browser-managed dialogs/tooltips remain visually unverified. The theme styles custom tooltip/hover surfaces; native title tooltips and native prompt/confirm windows are browser-managed. No commit or push was made.
